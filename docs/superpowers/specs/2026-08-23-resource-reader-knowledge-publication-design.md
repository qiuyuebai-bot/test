# 统一资源阅读器与专属讲义入库审批设计

## 1. 背景与目标

当前实操指南、分阶测试题和专属讲义主要在资源页面右侧的固定高度窗口中预览。该窗口适合快速浏览，但不适合阅读长篇 Markdown 内容，尤其在岗位培训嵌入页面和移动端更明显。

另一方面，经过审核的专属讲义具有复用价值，但当前领域知识库只支持管理员上传或创建文档，没有从已生成讲义提交、审核、发布和追溯的完整流程。

本功能包含两个边界清晰的模块：

1. 统一资源阅读器：为三类资源提供独立、全宽、可恢复阅读位置的阅读页面。
2. 专属讲义入库审批：允许合格讲义提交申请，由管理员审核后作为二级来源发布到对应领域知识库。

成功标准：

- 三类资源可以从资源页和岗位培训页进入同一个独立阅读页。
- 学习者无法获得分阶测试题答案，教师和管理员可以按需查看。
- 讲义所属学习者、教师和管理员可以提交符合条件的专属讲义。
- 只有管理员可以批准、驳回或重试知识库发布。
- 审核通过并成功索引后，讲义在同领域全局可检索，并可追溯到原资源和原始知识来源。
- 发布失败不会显示为已入库，也不会产生不可识别的孤立知识文档。

## 2. 范围与非目标

### 2.1 本期范围

- 新增资源独立阅读路由和页面。
- 保留现有右侧窗口作为快速预览。
- 新增讲义入库申请、管理员审核、发布重试和状态查询。
- 新增申请记录及资源、知识库文档之间的追溯关系。
- 将已入库讲义标记为审核生成的二级来源。
- 在知识库管理页增加入库审核视图。
- 增加权限、状态流转、索引失败和阅读交互测试。

### 2.2 非目标

- 不将阅读位置计入课程完成度、学习时长或考核成绩。
- 不允许实操指南和分阶测试题申请加入知识库。
- 不允许生成讲义未经管理员审核直接进入知识库。
- 不新增组织级或个人级知识库隔离；审核通过的讲义按领域全局共享。
- 不重做现有资源生成、知识库上传或向量检索架构。

## 3. 角色与权限

| 动作 | 讲义所属学习者 | 教师 | 管理员 |
| --- | --- | --- | --- |
| 阅读有权访问的资源 | 允许 | 允许 | 允许 |
| 查看测试题答案与解析 | 禁止 | 允许 | 允许 |
| 提交自己的专属讲义 | 允许 | 允许 | 允许 |
| 提交授权范围内其他学习者的讲义 | 禁止 | 允许 | 允许 |
| 查看自己的申请状态 | 允许 | 允许 | 允许 |
| 查看全部待审核申请 | 禁止 | 禁止 | 允许 |
| 批准、驳回、重试发布 | 禁止 | 禁止 | 允许 |

学习者只能提交其本人画像下的专属讲义。教师只能提交其现有授权范围内可访问的学习者讲义；本期沿用当前教师学习者列表的授权边界，不引入新的教师与学习者关系模型。管理员可以处理全部资源和申请。

本期不强制双人复核。管理员提交的申请允许由本人批准，以支持单管理员部署；提交与批准动作必须分别写入审计日志，并在审核详情中明确显示同一操作者。后续如需更严格治理，可在不改变状态机的前提下增加“提交人与审核人不得相同”的部署策略。

资源详情及测试答案权限必须由后端执行。前端隐藏按钮或折叠答案不构成权限控制。

## 4. 统一资源阅读器

### 4.1 路由与入口

新增受登录保护的路由：

```text
/resources/:resourceId/read
```

入口包括：

- 主资源页列表项标题。
- 主资源页快速预览区的“阅读”按钮。
- 岗位培训资源列表项和预览区的“阅读”按钮。
- 已入库申请关联的原讲义链接。

现有快速预览继续用于选中资源后的短时查看，不再承担完整长文阅读。主资源页和岗位培训页只跳转到统一阅读器，不分别实现第二套阅读正文。

### 4.2 页面结构

阅读页由三个区域组成：

1. 顶部工具栏：返回、资源类型、审核状态、入库状态、目录、字号、打印、复制和导出。
2. 章节目录：桌面端位于正文左侧并可折叠；移动端通过目录图标打开抽屉。
3. 正文：使用适合长文的居中版心，不嵌套装饰性卡片。

实操指南和专属讲义根据 Markdown 标题生成目录。分阶测试题根据题目结构生成题目导航。标题和目录项使用稳定锚点，刷新或复制章节链接后仍能定位到对应章节。

字号使用小、中、大三级分段控制。阅读位置以当前用户和资源 ID 为键保存在浏览器本地，重新打开时恢复。该数据仅用于浏览便利，不上传服务端，也不计入学习完成度。

打印样式隐藏全局导航、目录、按钮和状态操作，只输出标题、必要元信息和正文。复制和导出继续复用规范化后的资源正文，避免复制审核包或异常生成结构。

### 4.3 分阶测试题规则

- 学习者接口响应不包含正确答案和解析，阅读页显示题目并提供“开始练习”。
- 教师和管理员可以使用“查看答案”开关显示答案与解析。
- “开始练习”进入现有练习流程，传递学习者、资源和主题上下文；阅读页不另建答题引擎。
- 测试题导出遵循同一权限规则，学习者导出的内容不包含答案。

### 4.4 阅读异常状态

- 资源不存在：显示资源不存在页面并提供返回资源列表。
- 无访问权限：显示无权访问，不泄露资源标题或正文。
- 正文为空：显示暂不可阅读并允许返回。
- 历史正文格式异常：显示格式异常提示，允许有权限用户导出规范化前可用原文，但禁止提交知识库申请。
- 资源加载失败：保留页面框架并提供重试。

## 5. 专属讲义入库审批

### 5.1 申请前置条件

提交时必须同时满足：

- 资源类型为 `lecture`。
- 申请人具有提交该资源的权限。
- 资源为最新版本且正文非空、格式有效。
- 资源已完成质量校验并通过。
- 未检测到幻觉。
- 资源状态允许阅读和发布。
- 同一资源版本不存在待审核、发布中或已入库申请。

不满足条件时返回具体、可操作的失败原因，不创建申请记录。

### 5.2 申请快照

申请记录保存提交时的不可变快照，包括：

- 资源 ID、资源版本、正文内容哈希。
- 标题、正文、摘要、行业、主题、分类和标签。
- 原资源引用的文档 ID、切片 ID 和参考链接。
- 质量校验结果、幻觉检测结果和提交人。

管理员审核的是该快照。原讲义在申请后发生修改，不会改变待审核内容。修订后的讲义作为新版本重新申请。

### 5.3 状态机

```text
待审核 --批准--> 发布中 --索引成功--> 已入库
   |                 |
   +--驳回----------+--索引失败--> 发布失败 --重试--> 发布中
```

规则：

- 驳回必须填写原因。
- 只有待审核申请可以批准或驳回。
- 只有发布失败申请可以重试。
- 已入库申请不可再次批准；新内容必须生成新资源版本并重新申请。
- 状态更新使用条件更新或数据库锁，防止管理员重复点击造成重复文档。

### 5.4 发布过程

管理员批准后，系统先原子地将申请置为发布中，并创建或绑定唯一知识库文档记录；随后复用现有文档解析、切片和向量索引服务。

发布时将申请快照正文保存为不可变 Markdown 文件，文件名包含资源 ID、版本和内容哈希，存储在现有知识文档目录下。知识库文档的 `file_path` 指向该文件，解析和重建索引均以此快照文件为准，不读取可能已经更新的原资源正文。

索引成功后：

- 知识库文档状态为 `ready`。
- 申请状态变为已入库并记录知识库文档 ID。
- 文档在对应行业中全局可检索。
- 原讲义阅读页显示“查看知识库文档”。

索引失败后：

- 知识库文档保留错误状态和错误摘要，但不参与检索。
- 申请状态变为发布失败。
- 管理员可从同一申请重试，不创建重复申请或重复有效文档。

## 6. 数据设计

新增知识库发布申请实体，建议字段：

| 字段 | 用途 |
| --- | --- |
| `id` | 申请 ID |
| `resource_id` | 原专属讲义 ID |
| `resource_version` | 申请时资源版本 |
| `content_hash` | 申请快照正文哈希 |
| `snapshot` | 标题、正文、摘要、领域、来源和质量证据快照 |
| `status` | pending/publishing/published/rejected/publish_failed |
| `submitted_by` | 提交用户 ID |
| `reviewed_by` | 审核管理员 ID |
| `review_note` | 驳回原因或审核备注 |
| `knowledge_doc_id` | 发布后的知识库文档 ID |
| `error_message` | 脱敏后的发布失败摘要 |
| 时间字段 | 提交、审核、发布及更新时间 |

唯一性约束应保证同一 `resource_id + resource_version + content_hash` 不会存在多个有效申请。应用层同时处理历史驳回后新版本重新提交的规则。

知识库文档增加 `origin_type` 和 `origin_resource_id`：审核生成讲义分别写入 `generated_lecture` 和原资源 ID。发布申请保存 `knowledge_doc_id`，由此稳定查询以下关系：

```text
原始知识文档/切片 -> 生成讲义 -> 发布申请 -> 入库知识文档 -> 后续生成资源
```

## 7. 二级来源与检索规则

审核生成讲义属于二级来源，不与原始教材、标准或行业文档等同：

- 标记来源类型为审核生成讲义，并记录原资源及原始引用。
- 可以参与教学内容检索和后续资源生成。
- 检索结果展示其二级来源身份。
- 幻觉判定和事实证明优先使用原始文档。
- 单个生成讲义不能独立将某项事实判定为高可信。
- 知识溯源展示完整生成和发布路径，避免将生成内容伪装成原始资料。

该规则用于降低生成内容循环引用和错误放大的风险，同时保留优质讲义的教学复用价值。

## 8. 接口设计

继续使用现有资源详情和资源导出接口，并确保它们按角色执行答案脱敏。新增接口建议如下：

```text
POST /resources/{resource_id}/knowledge-publication-requests
GET  /resources/{resource_id}/knowledge-publication-request

GET  /knowledge/publication-requests
GET  /knowledge/publication-requests/{request_id}
POST /knowledge/publication-requests/{request_id}/approve
POST /knowledge/publication-requests/{request_id}/reject
POST /knowledge/publication-requests/{request_id}/retry
```

资源侧接口用于提交和读取当前资源版本的申请状态。知识库侧接口用于管理员审核和发布管理。所有写操作记录审计日志，包括资源、版本、申请、操作者、状态变化和结果，但不在日志中保存完整正文。

错误响应使用稳定业务错误码区分：资源类型不允许、质量未通过、检测到幻觉、内容已变更、重复申请、无权限、状态冲突和发布失败。客户端根据错误码显示对应操作提示。

## 9. 前端状态与操作

专属讲义阅读页根据申请状态展示：

- 可申请：显示“申请加入领域知识库”。
- 待审核：禁用重复提交，显示提交时间。
- 发布中：显示发布和索引进度状态。
- 已入库：显示“查看知识库文档”。
- 已驳回：显示驳回原因；新版本可重新申请。
- 发布失败：学习者和教师只看到失败状态；管理员可重试并查看脱敏错误摘要。

知识库管理页新增“入库审核”视图，支持按状态、行业、提交人和时间筛选。审核详情展示申请快照、原讲义链接、质量结果、幻觉结果、原始引用和版本信息。批准和驳回都需要二次确认，驳回必须填写原因。

## 10. 一致性与安全

- 服务端执行所有资源归属、角色、类型和质量校验。
- 申请读取权限不得泄露其他学习者的资源或申请信息。
- 管理员批准使用幂等处理，重复请求返回当前状态。
- 发布过程不把外部索引调用包在长数据库事务中。
- 知识文档只有在索引成功且状态为 `ready` 时参与检索。
- 错误消息不得包含密钥、内部绝对路径、供应商响应正文或堆栈。
- 审计日志保存操作证据，不复制讲义全文。
- 内容哈希用于版本一致性和重复发布判断，不作为访问凭证。

## 11. 测试与验收

### 11.1 后端测试

- 学习者只能阅读和提交自己的资源。
- 教师只能处理当前授权范围内的讲义，管理员可处理全部。
- 学习者获取和导出测试题时不包含答案与解析。
- 非讲义、未校验、校验失败、检测到幻觉、正文异常和旧版本不可提交。
- 重复提交被拒绝，真实的新版本可以重新申请。
- 管理员批准、驳回、重复批准和非法状态转换行为正确。
- 索引成功建立文档和追溯关系；索引失败进入发布失败且可幂等重试。
- 二级来源不会单独成为高可信事实证据。
- 所有关键写操作产生审计记录。

### 11.2 前端测试

- 主资源页和岗位培训页均能进入同一阅读路由。
- 三类正文、目录、锚点、字号、复制、打印和导出行为正确。
- 移动端目录使用抽屉且正文无横向溢出。
- 阅读位置可恢复且不会写入学习完成度。
- 学习者无答案控件，教师和管理员有答案开关。
- 讲义入库按钮和状态严格跟随后端状态。
- 管理员审核列表、审核详情、驳回原因和重试操作可用。
- 资源不存在、无权限、加载失败和格式异常均有明确状态。

### 11.3 最终验收场景

1. 学习者从岗位培训页打开一份长篇实操指南，在独立阅读页使用目录跳转，返回后原页面上下文保持不变。
2. 学习者打开分阶测试题看不到答案，点击开始练习进入现有练习流程。
3. 教师打开同一测试题可以主动显示答案和解析。
4. 学习者提交自己的合格专属讲义，看到待审核状态且不能重复提交。
5. 管理员核对快照和质量证据后批准，索引完成后讲义在对应行业可检索。
6. 从新知识文档可以追溯到发布申请、原讲义和原始知识切片。
7. 模拟索引失败时申请显示发布失败，重试成功后只产生一个有效知识文档。

## 12. 实施顺序

1. 增加发布申请数据模型、迁移、权限与状态服务。
2. 增加提交、审核、驳回、重试和状态查询接口及后端测试。
3. 接入现有知识解析、切片和索引流程，补齐二级来源与追溯。
4. 建立统一资源阅读路由和页面，并接入现有资源详情、导出和练习流程。
5. 将主资源页和岗位培训页的完整阅读入口切换到统一阅读器。
6. 在知识库管理页增加入库审核视图。
7. 完成前端测试、后端全量回归、类型检查、lint、生产构建和关键页面人工验证。
