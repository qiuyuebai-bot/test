# 学习者画像诊断与低分练习联动设计

## 1. 背景

`LearnerProfile` 当前把基本资料、学习风格、六项能力滑杆和知识盲区放在同一个编辑弹窗中。学习风格没有解释，能力分数依赖主观自评，雷达图也只是展示，不能把薄弱维度转成可执行的练习入口。

本次目标是降低画像填写的认知负担，并让能力结果能进入后续自适应导学。能力分数以短诊断题的系统估算为主，手动修正为可选项；首次诊断按六个维度各完成 2-3 题，总量 12-18 题，普通练习继续提供增量证据。

## 2. 目标与范围

### 目标

- 将画像创建和编辑拆成渐进式步骤，每一步只处理一类任务。
- 为学习风格提供可观察行为示例，并允许选择“不确定”。
- 通过服务端维护的诊断会话，为六个能力维度生成、判分并聚合 2-3 道题的结果。
- 返回系统估算分数、置信度、答题数和评估时间，并保留手动修正与原始估算。
- 让能力详情和雷达图的薄弱维度进入带维度上下文的 `/guidance` 会话。
- 让后续普通练习按题目维度增量更新系统估算，不覆盖手动修正记录。
- 保持现有 `LearnerProfile` 字段、旧画像编辑和普通导学接口兼容。

### 非目标

- 本次不重做普通导学的自适应难度算法。
- 本次不把自由文本知识盲区直接转换成虚假的资源 ID；没有可靠映射时进入该维度诊断或主题导学。
- 本次不删除旧画像中的滑杆字段或旧 API。
- 本次不扩展到新的画像字段（目标行业、岗位、学习目标）的完整采集；只保留现有数据的兼容展示。

## 3. 方案

采用独立诊断会话接口，复用现有题目生成和服务端判题能力。普通导学继续使用现有 `/tutoring/*` 接口，诊断会话拥有独立的模式标识和聚合逻辑。

### 3.1 诊断流程

```text
画像向导 -> 创建诊断会话 -> 六维各生成 2-3 题
         -> 逐题作答/自动保存 -> 服务端按维度累计证据
         -> 完成后返回分数、置信度和证据摘要
         -> 用户可选手动修正 -> 保存画像
         -> 低分维度进入 /guidance?dimension=...&learnerId=...
```

诊断会话必须支持恢复。服务端保存题目归属维度、题目顺序、答题结果和完成状态；客户端只保存当前步骤和最后一次服务端响应作为断网恢复辅助，不能把客户端分数当作可信结果。

### 3.2 数据边界

诊断题复用 `IssuedTutoringQuestion` 的服务端答案保护机制，并增加以下元数据：

- `assessment_mode`: `diagnostic` 或 `practice`
- `ability_dimension`: 六个画像维度之一
- `diagnostic_session_id`: 诊断会话 ID

诊断结果保存为画像的估算元数据，至少包含：

- `estimated_score`
- `confidence`
- `answered_count`
- `last_assessed_at`
- `manual_adjustment`（可空）

现有六个数值字段仍作为兼容的最终展示值。最终展示值由服务端按明确规则计算：系统估算值叠加手动修正，修正限制在 `0-100`；系统重新估算时更新估算值和置信度，不删除修正记录。

### 3.3 评分规则

- 每个维度至少完成 2 道题才生成该维度分数；否则返回 `insufficient_evidence`。
- 单题得分先按判题结果归一化为 `0-100`，再按题目难度做有限权重调整，防止难度等同于能力。
- 置信度由答题数量、结果一致性和覆盖的难度范围计算，初始版本使用可解释的确定性规则。
- 普通练习只有在题目带有 `ability_dimension` 时才更新对应维度；无法映射的主题不改变六维估算。
- 雷达图只是概览；低分列表必须提供键盘可达的文本入口。

### 3.4 前端交互

画像向导步骤：

1. 基本信息：姓名、学历、专业。
2. 学习偏好：四种风格均显示简短行为示例，并提供“不确定”。
3. 能力诊断：显示六维进度和当前题号，每次只显示一题；可暂停并恢复。
4. 结果确认：显示系统估算、置信度、证据数和低分维度；手动修正为折叠的可选操作。
5. 知识盲区：以可添加/删除标签呈现，继续提交旧的字符串数组格式。

基本资料中的必填项在进入诊断前校验；诊断题不能跳过，非必填知识盲区可跳过。编辑旧画像时，如果已有诊断结果直接展示结果步骤；用户可重新发起诊断。

`/guidance` 读取 `dimension` 和 `learnerId` 查询参数，将维度作为默认主题或诊断上下文。没有可用主题时显示维度诊断入口，不生成无关练习。

## 4. 接口与组件边界

### 后端

- `diagnostic` 域：会话创建、题目读取、答题提交、结果查询。
- `LearnerProfile`：保存估算元数据和最终兼容分数。
- `AdaptiveTutoringService`：复用题目生成、答案校验和知识检索，不承担诊断会话状态。
- 普通导学答题：读取题目维度元数据，成功提交后调用增量画像更新。

### 前端

- `LearnerProfile.tsx`：保留列表和详情展示，编辑入口改为 `LearnerProfileWizard`。
- `LearnerProfileWizard`：只负责步骤、表单状态、恢复和保存编排。
- `DiagnosticSession`：只负责诊断题的加载、答题、进度和结果。
- `coreApi` 或独立 `diagnosticApi`：封装诊断接口；普通导学 API 不改变现有调用约定。
- `AdaptiveGuidance`：解析维度查询参数并传给 `GuidanceLauncher`/会话启动逻辑。

## 5. 异常与兼容

- 诊断题生成失败：保留已答结果，显示重试；不写入半成品分数。
- 答题重复提交：服务端以题目/会话唯一约束幂等处理。
- 会话过期：返回可恢复的错误，允许重新生成未答题，不清除已完成维度。
- 老画像无估算元数据：按旧六维值展示“历史数据”，允许重新诊断。
- 诊断接口不可用：画像仍可保存基本资料和偏好，但明确标记能力待评估。
- 权限继续复用现有学习者数据权限检查；诊断结果不能通过前端 learnerId 越权读取。

## 6. 验收与测试

- 后端单测覆盖：六维题量约束、维度聚合、证据不足、置信度、重复提交、权限和普通练习增量更新。
- 前端单测覆盖：向导步进、回退/恢复、风格说明、不确定选项、结果与手动修正展示、旧画像回填。
- E2E 覆盖：新用户完成 12-18 题诊断、刷新恢复、保存画像、低分维度跳转 `/guidance`、普通练习后重新读取估算结果。
- 回归验证：`npm run typecheck`、相关 Vitest、画像与导学 E2E。
- 产品指标：诊断完成率、平均完成时长、每步退出率、证据不足比例、低分维度练习启动率。

## 7. 分阶段计划

### 阶段一：数据契约与诊断服务

新增诊断数据模型/迁移、服务端接口、六维聚合规则和权限测试；扩展下发题目元数据并保留普通导学兼容。

### 阶段二：前端向导与结果展示

拆分画像编辑弹窗，接入诊断会话，增加学习风格解释、暂停恢复、结果确认和手动修正；修复相关中文文案编码问题。

### 阶段三：低分维度导学与持续更新

让画像详情和雷达图进入带维度上下文的 `/guidance`，为普通答题补充维度增量更新，补充端到端验证和指标埋点。

## 8. 风险与假设

- 当前题目生成器能稳定返回可绑定到六个维度的题目；若知识库无法提供维度主题，使用确定性维度兜底题。
- 现有数据库通过 Alembic 增量迁移管理；迁移必须兼容开发环境中已由 `create_all` 创建的表。
- 能力维度名称保持现有六项，避免一次改动影响报告、Dashboard 和 API 类型。
- 中文文件当前存在编码显示异常；修复仅限本任务触及的文案，避免无关大范围重编码。
