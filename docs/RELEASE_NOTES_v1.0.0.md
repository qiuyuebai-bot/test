# 知域引擎 v1.0.0

首个 Windows 桌面发行版本。知域引擎面向领域知识生成、个性化学习与多智能体协同决策，可作为独立桌面软件安装运行，无需用户自行启动前后端或配置 Python、Node.js、Redis、ChromaDB 等开发环境。

## 本次更新

### Windows 桌面安装版

- 新增 Electron 桌面应用外壳，双击桌面图标即可启动，不再需要执行 `start` 脚本并手动打开浏览器。
- 前端、后端与完整 Python 运行环境已整合进安装包；程序启动时自动启动本地服务并打开应用窗口。
- 安装包包含 Chroma、Sentence Transformers、Torch、NumPy、Pandas 等本地知识库与向量检索运行时，体积会大于轻量演示构建，但功能更完整。
- 安装包内置专业化窗口、任务栏、桌面与开始菜单图标，产品名称统一为“知域引擎”。
- 支持标准 Windows 安装、卸载、开始菜单入口、可选桌面快捷方式与静默安装。
- 程序数据、日志、SQLite 数据库均保存至当前 Windows 用户的数据目录，不写入安装目录，升级或卸载更安全。
- 卸载时可选择是否保留本地用户数据。
- 后端端口自动选择可用的本机端口，关闭程序时自动清理后台服务。

### 首次使用与登录

- 首次运行检测到尚无本地账户时，会引导创建本地管理员账号。
- 已有数据库时保持原有登录流程，不覆盖既有账户和业务数据。
- 桌面端继续沿用原有登录、权限校验与业务接口，不降低访问控制要求。

### AI 配置中心

- 新增按用户隔离的 AI 配置能力。每个账号可保存自己的服务商、模型、接口地址、密钥及高级参数，不会与其他账号混用。
- 支持官方接口、OpenAI 兼容接口、聚合平台、反向代理、自建网关、本地模型服务等多种接入方式。
- 覆盖 OpenAI Chat Completions、OpenAI Responses、Anthropic Messages、Gemini 原生接口及兼容协议适配。
- 支持模型列表获取、手动填写模型、真实生成请求连通性测试，以及按服务商与模型能力展示高级参数。
- 高级参数会根据模型能力进行兼容性处理，避免将不支持的参数发送给推理模型、Gemini、Claude、Kimi 等不同接口。
- API Key 与反代鉴权信息加密保存，读取接口与日志不会返回明文密钥。
- 云端接口会校验地址并拦截不安全的内网目标；本地模型服务可在受控场景下使用本机地址。
- 首次登录可完成 AI 配置，也可暂时跳过，之后随时在应用内重新配置。
- 生成资源、问答等模型调用会绑定当前登录账号，确保使用正确的个人配置。

### 资源生成体验优化

- 优化资源生成页面、嵌入式训练资源入口与任务反馈界面。
- 资源生成任务采用稳定的生命周期管理：提交后可查看阶段、进度与智能体协作信息。
- 支持 SSE 实时状态更新，并在连接中断时自动轮询恢复，不会因短暂网络波动直接误判任务失败。
- 刷新页面、切换页面或返回资源页后，可恢复当前学习者正在进行的生成任务。
- 防止重复提交，保证同一任务的结束状态仅处理一次。
- 优化生成完成后的资源定位、内容解析、资源类型识别与详情跳转体验。
- 后台任务会继承任务发起人的 AI 配置与数据权限，避免异步任务使用错误账号配置。

### 单机可用性与稳定性

- Redis、Celery、ChromaDB 等增强组件不可用时，程序可自动使用内存、后台任务或关键词检索等降级路径继续运行。
- 桌面环境避免启动时强制下载模型或依赖外部服务，离线和演示场景下仍可进入系统。
- 保留原有 Docker 与浏览器开发模式，不影响开发部署方式。

## 安装与体验

1. 在本页底部的 Assets 中下载 `ZhiyuEngine-Setup-1.0.0.exe`（安装程序内部名称、桌面图标和开始菜单名称仍为“知域引擎”）。
2. 双击安装包，按安装向导完成安装；默认会创建桌面快捷方式。
3. 通过桌面或开始菜单中的“知域引擎”启动。
4. 首次使用创建本地管理员账号。
5. 登录后可在 AI 配置中心连接自己的模型服务；没有 API Key 时可先跳过并体验无需模型调用的功能。

> 安装包未包含任何用户 API Key。请在软件内自行填写和保存个人配置。
>
> Windows 可能会因安装包暂未进行代码签名而显示“未知发布者”提示；请确认下载来源为本 GitHub Release。

## 本地生成安装包

开发者在项目根目录执行：

```powershell
npm run build:electron
```

完成后，安装包位于：

```text
release\知域引擎-Setup-1.0.0.exe
release\知域引擎-Setup-1.0.0.exe.sha256
```

其中 `.sha256` 文件用于校验安装包完整性。`release` 目录已被 Git 忽略，不应提交到源码仓库。

## 后续自动发布安装包

后续修改源码并完成测试后：

```powershell
npm version patch --no-git-tag-version
git add .
git commit -m "feat: 更新内容说明"
git push origin main
git tag v1.0.1
git push origin v1.0.1
```

推送 `v` 开头且与 `package.json` 版本一致的标签后，GitHub Actions 会自动：

1. 在 Windows 环境安装依赖并构建桌面端；
2. 执行桌面端验证；
3. 生成新的 Windows 安装包与 SHA-256 校验文件；
4. 自动创建或更新对应的 GitHub Release；
5. 将安装包上传到 Release 的 Assets，供用户直接下载。为避免 Windows 命令行编码问题，GitHub Assets 使用 ASCII 文件名 `ZhiyuEngine-Setup-{version}.exe`，不影响软件内品牌名称。
