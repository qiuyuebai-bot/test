# 安全编码与应用防护

## 威胁建模
威胁建模从资产、边界、参与者和攻击路径出发识别风险。开发阶段尽早分析信任边界和滥用场景，可以降低后期修复成本。

## 输入校验与输出编码
输入校验应采用允许列表、类型检查、长度限制和业务约束，输出到不同上下文时使用对应编码。校验不能只依赖前端，服务端必须再次验证。

## 身份认证与会话
认证应安全存储口令，限制登录尝试并保护会话令牌。会话要设置有效期、撤销机制和安全属性，权限判断不能只依赖客户端传入的角色字段。

## 常见注入风险
SQL、命令、模板和路径注入通常源于把不可信输入当作代码或查询片段。参数化接口、固定命令集合和路径规范化是常见防护手段。

## 安全日志与错误处理
日志应记录足以定位问题的上下文，但不得泄露口令、令牌和敏感数据。对外错误信息应简洁，对内保留关联标识，并防止日志注入和异常堆栈泄露。
