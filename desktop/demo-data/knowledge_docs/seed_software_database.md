# 数据库设计与事务处理

## 数据建模
数据库设计应从业务实体、属性、关系和约束开始，区分主键、外键、唯一性和可空性。模型需要支持当前查询，也要为合理扩展保留空间。

## 关系规范化
规范化通过拆分重复信息减少更新异常，但过度拆分可能增加查询连接成本。设计时应在一致性、可维护性和查询性能之间进行权衡。

## 索引与查询优化
索引可以减少定位数据的扫描范围，但会增加写入和存储成本。应根据实际查询条件、排序和选择性设计索引，并使用执行计划验证效果。

## 事务与并发
事务通过原子性、一致性、隔离性和持久性保护一组操作。并发场景要关注脏读、不可重复读、幻读、锁等待和死锁。

## 备份与恢复
备份策略应明确全量、增量、保留周期、加密和恢复演练。只有成功恢复过的数据备份才具有实际保障价值，还要记录恢复点目标和恢复时间目标。
