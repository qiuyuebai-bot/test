# 持续集成与软件交付

## 持续集成基础
持续集成要求频繁合并代码，并自动执行构建、测试和静态检查。快速反馈可以降低集成成本，但前提是构建环境和测试数据稳定可复现。

## 制品与版本
构建制品应具有唯一版本标识，并保存依赖清单、构建信息和校验值。发布时使用不可变制品，避免同一版本在不同环境中内容不一致。

## 环境配置管理
环境差异应通过配置和基础设施描述管理，敏感配置放入安全存储。配置变更需要审计、评审和回滚机制，避免手工修改造成不可追踪问题。

## 灰度与回滚
灰度发布先让小范围用户或实例使用新版本，根据错误率、延迟和业务指标决定是否扩大范围。异常时应能快速回到已验证版本并保留现场信息。

## 交付安全
交付流水线应限制权限，保护令牌和构建凭据，扫描依赖漏洞和镜像风险。生产发布要有审批、审计和最小权限，避免流水线成为攻击入口。
